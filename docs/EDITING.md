# Монтаж с просмотром в FilmCraft

Основной процесс: **план сцен → утверждение → черновик FilmCraft → правки →
экспорт по команде**. Пользователю команды знать не требуется: их выполняет ИИ.
Чат и FilmCraft остаются открытыми рядом. Новые проекты входят в этот процесс
после `blocks`; старые можно перевести командой `edit plan`.

## 1. Согласовать монтажный план

После чистки уточните `work/blocks.json`. У каждого блока нужны `id`, `frames`,
`text`, `camera`, `visualizer` для графики, `metaphor` (действие в кадре),
`transition` и `sfx` (массив попаданий либо `false`). Тайминги — по чистой дорожке.

```sh
npm run edit -- plan --project ID
```

Покажите **весь** `work/plan.md`: номера, время, речь, действие, инструмент,
переход и звук. Команда выводит хеш версии. После явного согласия пользователя:

```sh
npm run edit -- approve --project ID --revision HASH
npm run scaffold -- --project ID
```

Изменение блоков или плана отменяет согласование. Нельзя утверждать план
самостоятельно ради обхода проверки. Просьба изменить конкретную сцену разрешает
эту правку; если меняется план, покажите новую версию и зафиксируйте её утверждение
в рамках уже данной просьбы, не запрашивая повторно то же разрешение.

## 2. Подготовить и открыть черновик

Напишите сцены по канону; подготовьте выбранные Animator/EffectCraft/Blender/
footage-клипы штатными командами. Затем:

```sh
npm run edit -- prepare --project ID
npm run edit -- open --project ID
```

`prepare` считает клипы сцен и отдельные дорожки и собирает `.fcproj`.
Финальный MP4 и `reference.mp4` не создаются. Повторная подготовка не перезаписывает
рабочий монтаж. Путь выводится командой и хранится в `work/edit-session.json`.

`open` запускает отдельное окно с локальным bridge. На macOS используется
`/Applications/FilmCraft.app/Contents/MacOS/FilmCraft`; другой путь задаётся через
`filmcraft.executable` или `FILMCRAFT_APP`. На Linux/Windows укажите desktop executable.
Токен создаётся автоматически в приватной временной папке ОС. Повторный `open`
подключается к тому же окну без переоткрытия проекта. После закрытия редактора
`open --restart` запускает новую сессию с **сохранённым** проектом. Несохранённые
правки старого окна сначала восстановите в самом редакторе.

## 3. Править в открытом редакторе

```sh
npm run edit -- inspect --project ID
```

Вывод содержит фактический документ, выделение/курсор и карту `objects.json`:
базовый клип `scene-0-b01`, подпись `b01/title`, субтитр `caption-N`.
Перед правкой сверяйте фактические ID. ИИ переводит просьбу в команды FilmCraft.
Например, `work/changes.json` (42 замените реальным ID из inspect):

```json
[{"id":"graphics.setText","params":{"clip":42,"layer":0,"text":"Новая подпись"}}]
```

```sh
npm run edit -- command --project ID --file projects/ID/work/changes.json
```

Параметры проверяйте через `filmcraft-cli describe COMMAND` установленной версии.
Перед правками сохраняется снимок в `history/` рядом с `.fcproj`, после — рабочий
проект. Окно обновляется напрямую. Для отмены можно передать команду `edit.undo`.
Список команд не является атомарной транзакцией: при ошибке прежние команды могут
быть уже применены. Остановитесь, прочитайте inspect и используйте Undo/снимок;
не повторяйте автоматически весь список.

### Изменение сложной анимации

Исправьте исходник сцены; при необходимости пересчитайте её выбранным инструментом:

```sh
npm run edit -- update --project ID --block b01
```

Система пересчитывает эту сцену и соседей, поскольку стык использует оба кадра,
а также их render-слои. Новые медиа заменяют mapped-клипы через native replacement.
Сохраняются монтажные ID, обрезки, эффекты и вручную исправленные нативные подписи.
Нативный текст меняйте через `command`, а не в JSX.

Общие файлы (`reel.tsx`, стиль, конфигурация), общий звук и другие изменённые сцены
требуют `--block all`. Это обновляет сгенерированные клипы внутри того же проекта.
Изменение структуры слоёв, хронометража, состава аудиодорожек или разбиения субтитров
останавливает обновление. Отдельный новый черновик можно получить через
`npm run filmcraft -- --project ID --snapshot`. Рабочая сессия при этом сохраняется;
перенос ручных правок в новую структуру и переход на неё требуют отдельного просмотра.
После согласованного перехода выполните `npm run edit -- adopt --project ID
--file /absolute/path/new.fcproj`, затем `edit open`. Старый проект остаётся целым.

## 4. Экспортировать согласованный результат

Только после команды пользователя «смонтировать/экспортировать видео»:

```sh
npm run render -- --project ID
```

Это экспорт **текущего FilmCraft-монтажа**. Редактор должен оставаться подключённым
с нужным проектом и секвенцией. Изменённые, но не обновлённые исходники блокируют
экспорт. Недоступные медиа и ошибки проверок не заменяют ранее выданный MP4.
Громкость нормализуется, затем выполняются штатные проверки. Результат:
`projects/ID/ID.mp4` либо настроенный `render.outputDir`.

Сложная графика требует просчёта в клипы. Текст/громкость меняются напрямую.
Внутренности цельного клипа не становятся объектами FilmCraft. Субтитры пока
экспортируются страницами без покадровой подсветки; типографика может отличаться
от Remotion. Остальные ограничения — `CRAFT.md`. Старые проекты без edit-сессии
продолжают собираться через Remotion.
