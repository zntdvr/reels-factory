# Виды контента и форматы

Вид контента выбирает конвейер, формат — структуру и способ подачи, а `style/` —
единое фирменное оформление. Формат подачи не равен размеру кадра.

| Вид | Первый формат | Материал | Результат |
|---|---|---|---|
| `history` | `narrated-story` — история без ведущего | сценарий → ElevenLabs, архивные кадры, фото, Remotion | MP4 9:16 и монтаж FilmCraft |
| `reel` | `presenter-cutaways` — человек и самостоятельные сцены | камера или озвучка, доступные визуализаторы | MP4 9:16 и монтаж FilmCraft |
| `carousel` | `educational` — одна мысль на слайд | тема, текст, расшифровка, изображения | PNG по порядку и HTML-предпросмотр для Instagram |

Все форматы используют «Синюю точку · systempartner»: `style/IDIOM.md`,
`style/tokens.ts`, общие шрифты и бумажный фон. Создавать отдельную палитру или
шрифтовой набор под формат нельзя. Если фирменные материалы отсутствуют,
запросить их у пользователя до оформления.

В текущей конфигурации оба видеовида — 1080×1920, 30 fps. Размер видео пока
задаётся общим `config/project.json`; индивидуальный размер есть у каруселей.
По умолчанию карусель — 1080×1350 (4:5), без зон под интерфейс Reels и субтитры.

## Приём

Команды выполняет агент; пользователь описывает задачу обычными словами.
Вид и формат следуют из запроса. При неясности уточнить вид до производства.

```sh
npm run content
npm run intake -- --type history --format narrated-story --name "История Microsoft" --topic "Как появилась Microsoft"
npm run intake -- --type reel --format presenter-cutaways --name "VPN для бизнеса" /path/camera.mp4
npm run intake -- --type carousel --format educational --name "Вопросы об IT" /path/text.md
```

`meta.json` содержит `content: { "type": "…", "format": "…" }`. Без `--type`
новый проект создаётся как `reel`; без `--format` берётся defaultFormat вида.
У старых проектов без `content` сохраняется прежний видеоконвейер и ограничения
не применяются задним числом. Не мигрировать существующие проекты автоматически.

Изображения сохраняются в `source/assets/`, их пути перечислены в `meta.assets`.
У историй видеофайлы тоже становятся материалом для иллюстраций, а не камерой
ведущего. У каруселей все медиа — материалы; они не запускают распознавание.
Исходники сохраняются, формат не превращает их автоматически в готовый контент.

## Историческое IT-видео

1. Исследовать тему: проверить даты, имена и причинно-следственные связи по
   первоисточникам; записать ссылки и факты в `source/research.md`.
2. Написать историю: зацепка → контекст → ключевые события → последствия →
   вопрос зрителю. Согласовать сценарий до озвучки.
3. Синтезировать через штатный `npm run tts -- --project ID --text-file …`.
   Голос и ключ ElevenLabs берутся из существующей настройки. Готовую озвучку
   ElevenLabs тоже можно принять файлом; не синтезировать её повторно.
4. При наличии меток от TTS перейти к cleanup; иначе сначала transcribe.
   Затем blocks и план, как в `PIPELINE.md` / `EDITING.md`.
5. Все блоки `camera: false`, без аватара. Инструменты — `footage` и `remotion`.
   Фото, логотипы и исторические документы показывать точно, архивные кадры
   не выдавать за другое событие. Сохранять источники материалов.
6. Утверждение плана → сцены → FilmCraft → правки → экспорт по команде.

Ограничение числа стоковых перебивок из канона рилсов не распространяется на
историю: здесь архивные кадры могут быть основой. Также не требуется добавлять
второй инструмент только ради разнообразия — пользователь допускает нарезки
либо Remotion. Фирменный стиль, читаемость, движение, точность фактов и баланс
звука остаются обязательными. Эти исключения не меняют правила рилсов.

## Рилс с человеком и сценами

Действует существующий конвейер `PIPELINE.md`. При видео с камеры нужны и
камерные, и графические блоки; смена на границах мысли, без механического
чередования через равное число секунд. При готовом аудио камерных блоков нет.
Инструмент выбирается для каждой сцены из доступных в рецепте. Новые форматы
рилсов добавляются отдельно и не меняют этот рецепт.

## Instagram-карусель

Тема → текст по слайдам → план → PNG-предпросмотр → правки → утверждение →
экспорт. Нет озвучки, кадровых таймингов, SFX и FilmCraft.

После intake заполнить `projects/ID/carousel.json`. Пустой список слайдов —
заготовка; система не выдаёт его за готовый пост.

```json
{
  "title": "Вопросы об IT",
  "canvas": { "width": 1080, "height": 1350 },
  "slides": [
    { "id": "cover", "role": "cover", "title": "Кто отвечает за вашу IT-систему:", "body": "Начните с этих вопросов." },
    { "id": "access", "role": "content", "title": "У кого есть доступы?", "body": "Попросите список владельцев ключевых учётных записей." },
    { "id": "cta", "role": "cta", "title": "Сохраните для разговора с командой", "body": "Подписывайтесь: разбираем IT-вопросы для владельцев бизнеса." }
  ]
}
```

У слайда также могут быть `stat` (крупное число) либо
`image: { "src": "source/assets/1-photo.jpg", "alt": "Описание изображения" }`.
Изображения — локальные PNG/JPG/WebP в `source/` или `work/public/` проекта.
Сетевые адреса сначала сохранить как исходники. Иллюстрации подготавливаются
под смысл поста; рендер не придумывает их автоматически.

Одна мысль на слайд, 2–9 слайдов. Первый — хук, последний — связанный с темой
призыв. Пользовательский хук не переписывать и не сокращать без просьбы;
правила текста — раздел 1 `GUIDE.md` и `knowledge/feedback.md`.
Обложке нужна осмысленная иллюстрация, если пользователь не попросил оставить
воздух. Названия компаний сохранять в оригинале, хештеги не добавлять.
Номер слайда и кнопки скачивания есть только в предпросмотре, не в PNG.

```sh
npm run carousel -- plan --project ID
npm run carousel -- preview --project ID
# После согласия пользователя; HASH берётся из plan:
npm run carousel -- approve --project ID --revision HASH
npm run carousel -- export --project ID
```

Предпросмотр проверяет фактическое переполнение текста в браузере: слишком
длинный текст останавливает сборку, а не обрезается и не уменьшается молча.
Агент дополнительно смотрит каждый слайд, проверяет смысл и читаемость на телефоне.
При недоступности браузера можно указать `--browser-executable PATH`.

Предпросмотр хранится в `work/carousel-preview-…/`, экспорт —
`projects/ID/carousel-export-…/`. В каждой папке есть PNG, `manifest.json`
с порядком слайдов и самостоятельный `index.html` с изображениями внутри.
Ранние версии сохраняются. Изменение текста, изображений, рецепта или стиля
сбрасывает пригодность прежнего утверждения для экспорта. Команда не публикует
пост в Instagram: она готовит изображения для загрузки.

## Добавление форматов

Реестр — `config/content-formats.json`, команда просмотра — `npm run content`.
Добавить запись в `types.<вид>.formats` с уникальным ID, названием, структурой,
политикой камеры, голосом и инструментами. Затем выбрать её через `--format`.
Политики камеры: `forbidden`, `optional`, `mixed-when-video`.
Голос: `none`, `elevenlabs`, `source-or-elevenlabs`. У slides-рецептов также
нужны `canvas` и `maxSlides`. Структура — инструкция автору сценария, а не
автоматический генератор текста. Список visualizers ограничивает видеоплан.

Добавление рецепта в рамках видео или слайдов не требует нового конвейера.
Новая механика (например, иная композиция карусели) потребует расширения
компонента/проверок, а новый вид результата — отдельного адаптера. Не обещать
поддержку произвольного формата одним названием в реестре.

## Проверка реализации

`node --test tests/content.test.mjs tests/edit-session.test.mjs` проверяет
маршрутизацию, ограничения форматов, совместимость и версии утверждений.
`npm run test:carousel` действительно рендерит тестовые слайды, проверяет PNG,
изображения, порядок экспорта и отказ при переполнении текста. Для локального
Chrome можно задать переменную `CAROUSEL_BROWSER` с путём к исполняемому файлу.
Тест не вызывает ElevenLabs и не публикует посты.
