# Фабрика роликов

Система собирает вертикальные ролики целиком: вы присылаете тему, текст, файл
озвучки или видео с камеры — получаете готовый mp4. Сначала утверждаете план сцен, затем
смотрите и правите черновик в FilmCraft рядом с чатом. Готовый MP4 — по вашей команде.

## Что нужно один раз

Поставьте вручную — остальное система установит сама:

1. **Node.js 20 или новее** — nodejs.org
2. **Приложение Claude** для Mac или Windows — claude.ai. Нужна платная подписка,
   Claude Code входит в приложение
3. **Только для Windows: Git** — git-scm.com

Дальше запустите установщик:

- **Mac:** щёлкните `install-mac.command` правой кнопкой и выберите «Открыть»
- **Windows:** запустите `install-win.bat`

Он поставит всё техническое — обработку звука, распознавание речи и её модели,
а также зависимости Animator в отдельное окружение внутри проекта. Потом проверит,
что всё установилось. Если какой-то шаг требует вашего пароля,
система не станет делать это тайком: она покажет ровно одну строку, которую нужно
выполнить, и подождёт.

Проверку можно повторить в любой момент:

```bash
npm run doctor
```

## Как соединить папку с Клодом

Установщик подготовил папку, но Клод про неё пока не знает:

1. запустите приложение Claude и войдите;
2. сверху по центру нажмите вкладку **Code** — не Chat: только у Code есть доступ
   к вашим файлам;
3. окружение оставьте **Local**, нажмите **Select folder** и укажите папку
   **`reelfactory`** — именно её, а не папку уровнем выше;
4. напишите «проверь, всё ли на месте».

Дальше система читает свои правила из папки сама.

## Как работать

Просто напишите, что нужно. Никаких команд заучивать не надо:

- «вот озвучка, тема — аналитика конкурентов, собери ролик»
- «есть видео с камеры, почисти запинки и оформи»
- «тема такая-то, напиши сценарий на 40 секунд»

Система сама заведёт папку проекта, разложит исходники, посчитает тайминги по
голосу и предложит план сцен с инструментами. После вашего утверждения подготовит
проект FilmCraft. Правки можно описывать в чате: они появятся в открытом редакторе.
Финальное видео экспортируется по вашей команде. Процесс описан в [docs/EDITING.md](docs/EDITING.md). Для рисованных по штрихам схем она может применить Animator, а для
настоящей объёмной сцены — Blender. Если фраза называет узнаваемое место или
предмет («Лондон — самый большой город»), система может поставить живые кадры:
найдёт их в вашем банке отрывков, на Pexels или на YouTube среди видео с
лицензией Creative Commons, а нужный кусок выберет модель CLIP прямо на
компьютере. ИИ сама выбирает инструмент по смыслу кадра.

Готовый ролик лежит в `projects/ID/ID.mp4` или в папке, заданной в `render.outputDir`.

Две команды всё же есть — обе про настройку, трогаются редко:

| Команда | Зачем |
|---|---|
| `/setup` | первая настройка: формат, озвучка, аватар |
| `/style` | подключить свой дизайн-код или обновить его |

## Важное правило: один ролик — один разговор

Новый ролик начинайте новым разговором. Так быстрее, дешевле и чище: старый
разговор тянет за собой весь предыдущий ролик и подталкивает систему повторять уже
использованные сцены.

Ничего не потеряется — всё хранится в файлах, а не в переписке. Правки только что
собранного ролика, наоборот, делаются в том же разговоре.

## Подробная инструкция

**Мануал** — руководство пользователя ко всему комплекту: общая часть, раздел 1
про карусели, раздел 2 про ролики, памятка и указатель. Тот же текст лежит в
`docs/GUIDE.md` — по нему система отвечает на вопросы о себе. Установка, все настройки, работа, субтитры, скрины, озвучка,
аватар и что делать, если что-то пошло не так. Читается один раз, дальше туда
заглядывают за конкретикой.

Оформление — ваш дизайн-код — вынесено в отдельную инструкцию, папка
`1. Оформление`: разбор с примером, на выходе HTML-файл с полным дизайн-кодом.

## Что где лежит

| Папка | Что там |
|---|---|
| `projects/` | ваши ролики. Папки создаёт система |
| `style/` | ваш стиль: цвета, шрифты, характер движения |
| `tools/Animator/` | встроенный инструмент рисованных whiteboard-сцен и его ресурсы |
| `footage/` | свой банк видеоотрывков для вставок; сами видео в git не попадают |
| `tools/footage-venv/`, `models/clip/` | подбор видеовставок: CLIP и свежий yt-dlp, ставит `npm run install-deps` |
| `tools/blender/` | локальная установка Blender, если она есть; путь задаётся в `config/project.json` |
| `config/` | настройки |
| `docs/` | правила производства и справка |
| `core/` | движок. Трогать не нужно |

## Подключить озвучку или аватар позже

В любой момент. Добавили ключ в `.env` — и следующий ролик уже можно озвучить
синтезом. Старые проекты не ломаются, переделывать ничего не нужно. Начали с
готовых mp3, через полгода перешли на генерацию голоса — система переживёт это
спокойно.

Animator использует свой файл `tools/Animator/.env`. После переноса проекта на
другую машину скопируйте туда `tools/Animator/env.example` как `.env` и добавьте
`OPENROUTER_API_KEY`. Секреты не входят в переносимую копию проекта.

Для Blender команда `npm run doctor` проверяет путь `blender.executable`. На
другом компьютере установите Blender и обновите этот путь; сцены хранятся как
Python-файлы внутри проекта, готовый прозрачный WebM — в рабочей папке проекта.
